# 병원소식 관리자 사용 안내

관리자 메뉴에서 **병원소식 관리**를 열면 공지사항·언론/방송 보도·트레이닝센터·학술소식·연세척TV를 함께 관리할 수 있습니다.

## 게시물 관리

- 게시판 탭, 제목/내용 검색, 최신순/오래된순, 20건 단위 페이지 이동을 지원합니다.
- 제목 또는 보기를 누르면 관리자 상세 화면으로 이동합니다. 수정·삭제·홈페이지에서 보기 버튼이 있습니다.
- 수정 후에는 검색 조건과 목록 페이지를 유지합니다. 새 글은 해당 게시판 목록에서 강조 표시됩니다.
- 삭제는 확인창을 거치는 영구 삭제입니다. 삭제가 성공한 뒤 사용하지 않는 관리 대상 이미지 파일을 정리합니다.

## 글쓰기와 이미지

- 본문 위 도구 모음에서 문단/소제목, 크기, 글자색, 형광펜, 굵게/기울임/밑줄/취소선, 정렬, 목록, 인용, 구분선, 링크를 설정합니다.
- 실행 취소/다시 실행과 서식 지우기를 제공합니다. 외부 문서를 붙여넣으면 기본 서식을 유지하면서 불필요한 서식을 정리합니다.
- 캡처한 이미지나 클립보드 이미지 파일은 Ctrl+V 또는 ⌘+V로 본문에 넣습니다. 파일 끌어놓기와 이미지 버튼도 지원합니다.
- 외부 웹 문서에 연결된 이미지 URL은 자동으로 가져오지 않습니다. 이미지 자체를 복사하거나 파일로 첨부합니다.
- 본문 이미지를 선택하면 너비(25/50/75/100%), 정렬, 설명, 대체 텍스트를 설정할 수 있습니다. 끌어서 위치를 옮길 수 있습니다.
- 첨부·대표 이미지 영역에서 대표 이미지, 상단 첨부 이미지 순서와 제거를 관리합니다. 본문에 들어간 이미지는 상단 갤러리에 반복 표시하지 않습니다.
- 본문과 첨부를 합쳐 서로 다른 이미지 최대 10개, 파일당 20MB이며 JPG/PNG/WEBP/GIF를 지원합니다.
- 업로드 진행률과 실패 시 재시도를 표시합니다. 업로드 중에는 저장을 막아 불완전한 이미지를 게시하지 않습니다.
- 미리보기에서 PC·모바일 너비로 본문 배치를 확인합니다.

## 임시보관

작성 내용은 약 0.7초 후 현재 브라우저의 localStorage에 보관됩니다. 게시판별 새 글 1개와 각 기존 글의 수정 내용을 따로 보관합니다. 다시 열면 이어서 작성 또는 임시보관 버리기를 선택합니다.

업로드가 끝난 이미지도 복구됩니다. 업로드 도중 브라우저를 종료한 파일은 재첨부해야 합니다. 다른 기기와 동기화하지 않으며 브라우저 저장소를 삭제하면 임시보관도 없어집니다. 저장소를 사용할 수 없으면 안내를 표시합니다.

링크 이동과 창 닫기/새로고침 시 작성 중인 내용이 있으면 안내합니다. Navigation API를 지원하는 브라우저에서는 같은 문서 내 뒤로/앞으로 이동도 확인합니다. 이전 브라우저에서도 뒤로 이동할 때 임시보관을 갱신합니다.

## 저장 구조와 운영

추가 DB 마이그레이션은 필요하지 않습니다. 기존 hospital_news 테이블을 사용합니다.

- 기존 일반 텍스트 content는 그대로 읽습니다.
- 새 본문은 content에 `ys-news-rich:v1:` 접두사와 검증한 Tiptap 문서 JSON을 저장합니다. 접두사에는 multipart 전송이 바꿀 수 있는 줄바꿈을 넣지 않습니다.
- 공개 화면은 허용한 노드·속성만 React로 렌더링합니다. 저장된 HTML을 직접 실행하지 않습니다.
- 관리자 검색, 공유 설명, 메인 연세척TV 해시태그는 문서에서 추출한 일반 텍스트를 사용합니다.
- image_urls[0]을 대표 이미지로 사용합니다. 상단 갤러리 순서는 문서의 galleryOrder 속성에 별도로 보관합니다.
- reviews 버킷의 `news/{게시판}/{게시물 ID}/{임의 파일명}` 경로로 인증된 관리자의 서명 업로드를 사용합니다. 큰 파일을 Next Server Action 본문으로 보내지 않습니다.
- 저장 시 새로운 이미지의 소유 경로, 저장 완료 여부, MIME, 크기를 다시 확인합니다.
- 기존 글 수정 시 처음 읽은 값과 비교해 오래된 편집 화면의 덮어쓰기를 거부합니다.
- 이미지 제거는 DB 저장/삭제 성공 후 진행하며, 다른 병원소식이 참조하는 파일과 news 경로 밖의 파일은 삭제하지 않습니다. 정리 실패는 게시물 저장 성공과 구분해 안내합니다.
- 임시보관을 명시적으로 버리거나 글을 저장할 때 해당 작성 과정의 미사용 파일을 정리합니다. 브라우저 저장소만 지운 뒤 방치된 파일을 정기 삭제하는 배치는 포함하지 않습니다.
- 변경 후 관리자 목록, 공개 목록/상세, 메인, 사이트맵 캐시를 갱신합니다.

공개·비공개 전환, 휴지통·복원, 글 복제, 예약 발행, 기기 간 임시저장 동기화는 후속 범위입니다.

## 검증

```sh
npm run test:news
npx playwright install chromium
npm run test:news:browser
npm run build
```

브라우저 검증은 3211 포트의 별도 Next 개발 서버와 4312 포트의 Supabase 호환 테스트 서버를 실행합니다. 테스트 환경의 URL·키를 별도로 지정하므로 운영 게시물이나 이미지에 쓰지 않습니다. 테스트용 Next 캐시는 `.next/news-tests`에 둡니다.

기존 글 호환, 저장 왕복, 서식/링크 검증, 갤러리 순서, 관리자 인증, 다섯 게시판 CRUD, 이미지 붙여넣기·크기·설명, 미리보기, 임시보관 복구, 업로드/저장 실패 후 재시도, 공개 표시, 이미지 정리, 이탈 안내, 동시 편집 충돌을 확인합니다.

편집기 연동 기준: [Tiptap Next.js 안내](https://tiptap.dev/docs/editor/getting-started/install/nextjs). Next.js 관련 처리는 프로젝트에 설치된 `node_modules/next/dist/docs/`의 Server Actions·Route Handlers·캐시 갱신 문서를 기준으로 합니다.
